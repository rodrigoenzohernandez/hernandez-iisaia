# Guía de despliegue — Supabase + Render + Vercel

Base en **Supabase**, API en **Render**, front en **Vercel**. Render y Vercel ya sirven HTTPS, así
que no hace falta túnel. Esta guía es para dejarlo andando de punta a punta.

**Modo elegido: `development` con CORS restringido.** No se setea `NODE_ENV=production` (evita tener
que montar Resend + dominio verificado y el problema de devDependencies en el build), pero el CORS
se limita a mano a la URL de Vercel + localhost. El transporte sigue siendo HTTPS igual.

> **Dónde van las variables:** el código lee `process.env` directo (Node 24, sin dotenv). En la nube
> **no se usan archivos `.env`**: cada variable se carga en el **dashboard** de la plataforma
> (Render → Environment; Vercel → Settings → Environment Variables). Supabase no recibe variables:
> *te da* la cadena de conexión.
>
> **Secretos:** este archivo trae solo **placeholders** y cómo generar/obtener cada valor. Los
> valores reales (`JWT_SECRET`, `ENCRYPTION_KEY`, tokens de MP…) se comparten por un canal privado
> (gestor de contraseñas / mensaje directo), **nunca** en el repo.

Orden recomendado: **1)** Supabase → **2)** Render → **3)** sembrar la base una vez → **4)** Vercel
→ **5)** configurar la app de Mercado Pago.

---

## 1. Supabase (base de datos)

1. Crear un proyecto. Anotar la contraseña de la base.
2. Botón **Connect** → sección **Session pooler** (NO "Direct connection" ni "Transaction pooler").
   Copiar esa cadena. Tiene esta forma:

   ```
   postgresql://postgres.<project-ref>:<DB_PASSWORD>@aws-0-<region>.pooler.supabase.com:5432/postgres?sslmode=require
   ```

   - **Puerto 5432** (Session pooler): es **IPv4** y sirve para migraciones *y* para la app. La
     conexión **directa** de Supabase es IPv6 y **Render free no la alcanza** → no conecta.
     (El Transaction pooler, puerto 6543, necesita `?pgbouncer=true` y complica las migraciones.)
   - Asegurarse de que termine en **`?sslmode=require`**.

3. Esa cadena es el `DATABASE_URL` que va en Render.

> Prisma 7 no lleva `url` en `schema.prisma`: toma `DATABASE_URL` del entorno para migrar y en
> runtime (ver `backend/prisma.config.ts`). Con un solo `DATABASE_URL` alcanza.

---

## 2. Render (API)

**Crear un Web Service** apuntando al repo. Configuración:

| Campo | Valor |
| --- | --- |
| Root Directory | `tp-final/backend` |
| Build Command | `npm install && npm run build && npx prisma migrate deploy` |
| Start Command | `npm run start:prod` |

- El `start:prod` **no migra**; por eso `prisma migrate deploy` va en el **build**.
- **No agregar `NODE_ENV=production`.** Si el build falla por falta de `nest`/`tsc`/`prisma`
  (Render a veces fuerza `NODE_ENV=production`, que hace a `npm install` saltear devDependencies),
  agregar la variable **`NPM_CONFIG_PRODUCTION=false`**.
- `PORT` lo inyecta Render solo; la API lo lee (`env.port`). No hace falta setearlo.

**Variables de entorno (Environment):**

| Variable | Valor / cómo obtenerla |
| --- | --- |
| `DATABASE_URL` | La cadena **Session pooler** de Supabase (paso 1) + `?sslmode=require` |
| `JWT_SECRET` | Generar: `openssl rand -base64 48` (mínimo 32 caracteres) |
| `ENCRYPTION_KEY` | Generar: `openssl rand -base64 32` (32 bytes). **La misma que se use al sembrar** (paso 3), o los tokens de MP guardados no se pueden leer |
| `SEED_ADMIN_PASSWORD` | Generar: `openssl rand -base64 18` (mínimo 12). Es la contraseña de los admins y del superadmin |
| `CORS_ORIGIN` | `https://pasate.vercel.app,http://localhost:3101` |
| `TRUST_PROXY` | `3` (los proxies que Render pone delante; sin esto el límite de peticiones se comparte entre todos) |
| `EMAIL_PROVIDER` | `log` — los mails (incluido el **código de ingreso de las clientas**) salen en los **logs de Render** |

> **CORS:** es una lista por coma de **orígenes** (esquema + host), **sin path y sin `/*`**. Por eso
> es `https://pasate.vercel.app` y no `https://pasate.vercel.app/*`. Agregá `http://localhost:3101`
> para poder apuntar un front local a la API desplegada.

## 3. Mercado Pago — variables en Render

Para cobro online con MP de producción, sumar en Render:

| Variable | De dónde sale |
| --- | --- |
| `MP_CLIENT_ID` | El número de la app de Mercado Pago |
| `MP_CLIENT_SECRET` | Credenciales de **producción** de la app (hay que pedir activarlas) |
| `MP_REDIRECT_URI` | `https://pasate.vercel.app/mercadopago/vuelta` (exacta, registrada en la app) |
| `MP_PLATFORM_ACCESS_TOKEN` | Access token de la cuenta **dueña de la app**: cobra las suscripciones de los centros |
| `MP_WEBHOOK_SECRET` | La clave secreta de **Webhooks** de la app |
| `PUBLIC_API_URL` | `https://<api>.onrender.com` — sin esto MP no tiene dónde avisar los pagos y **nadie cobra online** |
| `FRONTEND_URL` | `https://pasate.vercel.app` — la página de vuelta de quien paga |

Notas:
- `MP_PLATFORM_ACCESS_TOKEN` **exige** `MP_WEBHOOK_SECRET`, o la API no arranca.
- Cada centro conecta **su propia** cuenta de MP con el botón "Conectar con Mercado Pago" (OAuth);
  sus tokens quedan cifrados en la base. No se toca ninguna variable por centro.
- En este modo (sin `NODE_ENV=production`) se permite `MP_OAUTH_TEST_TOKEN=true`, útil para conectar
  cuentas **vendedoras de prueba** por OAuth. (En producción está prohibida.)

## 4. Sembrar la base una vez (desde tu compu)

El seed **no corre en el server** (borra la base, y se niega si `NODE_ENV=production`). Y el
**superadmin no tiene alta por API**: es la única cuenta que solo crea el seed. Así que hay que
sembrar a mano, una vez, apuntando a Supabase, con la **misma `ENCRYPTION_KEY` de Render** y sin
`NODE_ENV=production`:

```bash
cd tp-final/backend
DATABASE_URL="<cadena-de-supabase>" \
ENCRYPTION_KEY="<la-misma-que-en-render>" \
SEED_ADMIN_PASSWORD="<la-misma-que-en-render>" \
node prisma/seed.ts
```

Crea el superadmin (`superadmin@turnos.test`) y los centros `lo-de-lili`, `bella-piel` y
`centro-cerrado`. Todos entran con `SEED_ADMIN_PASSWORD`.

Opcional — conectar `lo-de-lili` a Mercado Pago con credenciales de prueba, sin OAuth:

```bash
SEED_MP_ACCESS_TOKEN="<token-de-prueba>" SEED_MP_USER_ID="<user-id>" \
ENCRYPTION_KEY="<la-misma-que-en-render>" DATABASE_URL="<cadena-de-supabase>" \
npm run mp:conectar-prueba -- lo-de-lili
```

## 5. Vercel (front)

**Importar el repo como proyecto.** Configuración:

| Campo | Valor |
| --- | --- |
| **Root Directory** | `tp-final/frontend` (es monorepo; sin esto Vercel no encuentra el proyecto — y el Root Directory es setting del dashboard, no de `vercel.json`) |
| Framework | Next.js (se detecta solo) |

**Variable de entorno:**

| Variable | Valor |
| --- | --- |
| `NEXT_PUBLIC_API_BASE_URL` | `https://<api>.onrender.com/api/v1` |

- `NEXT_PUBLIC_*` se **hornea en el build**: si cambia la URL de la API, **re-deploy**.
- No hace falta `API_BASE_URL_INTERNA`: el front usa `NEXT_PUBLIC_API_BASE_URL` también para el
  render del servidor cuando aquella no está (ver `src/lib/cliente.ts`).
- `next.config.ts` tiene `output: 'standalone'` (es para el Docker local); en Vercel no molesta y
  no hay que tocarlo.

## 6. Configurar la app de Mercado Pago (panel de MP, una sola vez)

Logueado con la cuenta **dueña de la app**:

- **Configuración de la aplicación:** la URL de vuelta exacta (`https://pasate.vercel.app/mercadopago/vuelta`)
  y el flujo *authorization code* con **PKCE**. Sin esto, MP muestra "La aplicación no está preparada
  para conectarse".
- **Webhooks → pestaña Modo productivo:** `https://<api>.onrender.com/api/v1/webhooks/mercadopago`,
  con el evento **Planes y suscripciones**. (Los cobros de cada centro no van acá: cada uno lleva su
  propia URL de aviso, que arma la API con `PUBLIC_API_URL`.)

Si un aviso de suscripción no llega, al abrir **Cobros** el backend le pregunta a MP el estado real.

- [ ] `curl https://<api>.onrender.com/api/v1/tenants/lo-de-lili/servicios` → **200** con el catálogo.
- [ ] `https://pasate.vercel.app` carga la landing de plataforma.
- [ ] Login de admin de `lo-de-lili` (`lili@lodelili.test` + `SEED_ADMIN_PASSWORD`) entra al panel.
- [ ] Login del superadmin (`superadmin@turnos.test`) entra al panel de plataforma.
- [ ] El código de ingreso de una clienta aparece en los **logs de Render**.
- [ ] Mercado Pago (si se configuró): en el panel de un centro → **Cobros**, la cuenta figura
      conectada; un cobro de prueba dispara el webhook.

## Gotchas (los que más cuestan)

- **Supabase:** usar el **Session pooler (5432)**, no la conexión directa (IPv6, Render no la
  alcanza). Siempre `?sslmode=require`.
- **Migraciones:** van en el **Build Command** (`prisma migrate deploy`), no al arrancar.
- **Seed:** no corre en el server; se siembra a mano desde la compu, con la misma `ENCRYPTION_KEY`.
- **Build de Render:** si se queja por `nest`/`tsc`, es `NODE_ENV=production` saltando devDeps →
  `NPM_CONFIG_PRODUCTION=false`.
- **Vercel:** el **Root Directory** `tp-final/frontend` es lo que más suele faltar en un monorepo.
- **Render free:** la API se **duerme a los 15 min** sin tráfico; el primer request después tarda, y
  un aviso de MP que llega mientras despierta puede reintentarse más tarde.
